# Procedural map generation: an interactive lab built on Herbert Wolverson's talk

The source of [christianjmills.com/posts/procedural-map-generation-techniques-notes/](https://christianjmills.com/posts/procedural-map-generation-techniques-notes/):
a map lab for the techniques of Herbert Wolverson's talk
[Procedural Map Generation Techniques](https://www.youtube.com/watch?v=TlLIOgWYVpI)
(Roguelike Celebration 2020). Each technique is a stage of a pipeline the reader can edit, step
through, measure over 200 seeds and walk, on one deterministic Rust core. Every claim about the
talk is cited to its recording by time, its slides by page or its code
([thebracket/roguelike-celebration-2020](https://github.com/thebracket/roguelike-celebration-2020))
by line, and every number of our own is regenerated by the build.

That URL still serves the old post until the site relaunches.

## Layout

```
page/
  content/page.mdoc             the page's frame, written by hand: its sections and their text
  content/cards/<stage>.mdoc    one technique's card: its opening line and its seven parts
  content/notes.mdoc            each kind of step's text, shown beside the step in the page
  gen.mjs                       writes deliverable/content/index.mdoc from those and lab/data/
  lib.mjs                       the data, the page's names, its measured values, the step figures
  tokens.json                   the site's colors the step figures are drawn in (a checked copy)
deliverable/
  manifest.json                 the deliverable's manifest (format 0.1)
  content/index.mdoc            the page, in the site's Markdoc dialect, citing passages by id.
                                Generated by page/gen.mjs and committed, because the trace reads it
  content/index.citations.json  passage ids resolved into the site's locators (`slib trace`)
  content/index.checking.json   the data for the page's "how this was checked" note (`slib note`)
  assets/lab/lab.js             the page's module: the lab, and each card's step-through
  assets/lab/rows.js            the open lab's rows and the room the page reserves for them;
                                the build folds it into the module
apply-citations.mjs             source-library's splicer, copied verbatim (source-library aa45a58)
build.mjs                       stages the bundle in dist/bundle/ and publishes it
lab/                            the map lab's deterministic Rust core, its WebAssembly binding, the
                                CLI for agents, the demo recipes, the recipe schema and the
                                measurement data (lab/README.md)
faithfulness/                   the talk's own code run without a window over many seeds, for the
                                faithfulness check and for the counts behind the page's table of
                                where the talk and its code differ (faithfulness/README.md)
rust-toolchain.toml, mise.toml  the Rust toolchain, wasm-bindgen and wasm-opt this repo pins
```

The page is published to the site as a deliverable bundle. The site repo,
[cj-mills/christianjmills](https://github.com/cj-mills/christianjmills), owns the format: its
`spec/README.md` describes the manifest, the dialect and the bundle.

## Writing the page

The text is in `page/content/`. A citation is written short, `[[t:73-74 s:9 c03:61-66]]` for the
talk's transcript segments, a slide and lines of a demo's code, `[[own]]` for our own reasoning
and `[[run:c03.regions.median]]` for a measured value the sentence states as
`{{c03.regions.median}}`. Lines starting `@@` are where a generated part goes: a card's
step-through, its measured table, its failing seeds, a rule's diagram. `page/gen.mjs` documents
them.

The text is distilled (one fact an item, in lists and tables under recurring lead-ins, with
sentences kept for reasoning), so an item is a claim and carries its own citation. A rule is a
numbered list with a citation a step. Where a rule is spatial, `@@diagram <name> alt="…"
caption="…"` and rows of characters, a character a tile, make a figure the build draws for both
themes (`diagram()` in `page/lib.mjs` lists the characters).

In the talk's code `.` is the solid tile and `#` an open one. The page says so once, and
`page/gen.mjs` declares the two passages of the shared map code that settle it as the page's
standing context, which the verifier reads with every claim, so no claim has to cite them.

A card's step-through opens on its first demo, as the last step of its fallback: the site shows
that step alone while the module loads, and the module opens at the same step and the same size,
so the swap moves nothing. The other demos' steps are a list of their own below it.

The lab at the page's head opens by itself. `page/gen.mjs` writes its open height on its tag
(`reserve="…"`, the site's spec, Interactives), the site holds the figure to that from the first
paint, and the module opens at mount, within it. The height is the module's own: open, every row
of the lab has a set height and the map follows the width, and `deliverable/assets/lab/rows.js`
holds the rows and their sum, for the module's CSS and for the tag. Change a row there and the
page changes with it; the site's build then reads the figure's height before and after the mount
at 16 window sizes and fails on any difference.

```sh
node page/gen.mjs            # writes deliverable/content/index.mdoc
node page/gen.mjs --check    # fails if the committed page isn't what it writes
```

## Checks

```sh
npm run check      # the lab core: tests, WebAssembly size and agreement with native, data regenerates
npm run measure    # regenerates lab/data/
```

They need the pinned Rust toolchain (`rust-toolchain.toml`, `mise.toml`).

## Build and publish

Node 26.13.0 and the pinned Rust toolchain. There are no other dependencies.

```sh
npm run build
```

stages the bundle in `dist/bundle/`:

- the page written again by `page/gen.mjs`, refused if the committed page differs, so every
  table, step and recipe link is regenerated from `lab/data/` and the core;
- each `{% cite %}` replaced by the site's `{% ref %}` locators from `index.citations.json`,
  refused if the page changed since it was traced;
- every `{% own-run values="…" /%}` value regenerated and checked against the sentence, table
  or list that states it;
- the manifest's `checked` from `index.checking.json`, which must describe this exact page;
- the core built as WebAssembly, with its glue, the page's names and the demos' recipes
  written into the module;
- every step figure drawn from the core's own frames, in the site's figure colors for both
  themes;
- the measurement data, the counts from the talk's own code (`faithfulness/talk-checks.json`)
  and the recipe schema, and `code.commit` set to `HEAD` when the working tree is clean.

The two JSON files beside the page stay out of the bundle. They hold ids, locators, counts and
states only, so a fresh clone rebuilds the bundle without the private source library.

`node build.mjs --draft` stages a page that isn't traced yet, with its citations left out, to
look at on the site's preview server. A draft can't be published.

## Citing and checking

The page cites passages of the talk's transcript, slides and code by their ids in the
author's private source library, which holds the evidence.
After editing the page, from the library's checkout:

```sh
node page/gen.mjs                                         # in this repo: write the page
slib trace  <this repo>/deliverable/content/index.mdoc   # resolve ids; writes index.citations.json
slib verify <this repo>/deliverable/content/index.mdoc   # a verdict for each claim citing a source
slib note   <this repo>/deliverable/content/index.mdoc   # writes index.checking.json
```

`npm run publish:r2` refuses a page with open flags.

Publishing runs the site's publish command, which verifies the bundle against the site's spec,
uploads it and pins it in the site's lockfile. It needs a checkout of the site repo with its
dependencies installed (`npm ci`), at `../christianjmills` beside this repo or wherever
`CHRISTIANJMILLS_SITE` points:

```sh
npm run publish:r2      # to the R2 bucket, with credentials from the site's tools/cloudflare.sh
DELIVERABLES_PUBLIC_URL=file:///tmp/bucket/ npm run publish:local   # to a local folder laid out like the bucket
```

`publish:r2` refuses a dirty tree or a commit that isn't pushed, because the bundle names the
commit it was built from. The lockfile change lands in the site checkout, to be committed
there.

To preview without publishing, point the site's `deliverables.local.json` at `dist/bundle/`
and run the site's `npm run dev`.
